# Review: 6.1-需求分析与架构设计.md

## 🔴 必改

### [R1] `/plan exit` 命令完全虚构（最严重的事实错误）
- **位置**: 第 5.2 节 / 第 668、680 行
- **问题**: 示例中使用 `/plan` 进入 Plan Mode 后，用 `/plan exit` 退出。但官方文档从未存在 `/plan exit` 命令
- **核实结果**: `/plan` 前缀确实存在（官方 Permission Modes 文档确认），但**退出 Plan 模式的官方方式是再次按 `Shift+Tab` 切换回其他模式**
- **修改建议**: 将示例中的 `/plan exit` 替换为官方支持的退出方式，例如：
  ```
  用户：[评审方案，确认无误后按 Shift+Tab 切换回 default 模式]
  
  用户：请按照刚才确认的方案实现 JWT SSO 集成。
  ```

### [R2] "Anthropic 官方最佳实践"来源拔高
- **位置**: 第 1.2 节 / 第 24 行、第 1047 行（[^1]）
- **问题**: 声称需求描述的结构化方法（业务背景→核心功能→约束条件→用户场景）基于"Anthropic 官方最佳实践"
- **核实结果**: `code.claude.com/docs/en/best-practices` 确实存在，但内容聚焦于 Claude Code 的使用技巧（上下文管理、CLAUDE.md 配置、权限模式、subagents 等），**并未包含与 6.1 节对应的需求描述框架**。该框架是通用软件工程实践
- **修改建议**: 改为"根据软件工程最佳实践和 Claude Code 社区经验"，或明确标注为"通用软件工程方法论"

### [R3] "30% 以上"百分比缺乏可验证来源
- **位置**: 第 1.2 节 / 第 114 行
- **问题**: 声称访谈式需求收集"通常能挖掘出 30% 以上你最初没想到的需求点"
- **核实结果**: 引用来源 [^3]（Ran Isenberg 博客）中无法找到"30%"或"一小时的头脑风暴产出了 36 个他原本未考虑到的用户流程"的对应内容。该精确百分比属于无来源的定量结论
- **修改建议**: 删除具体百分比，改为定性描述，如"这种访谈式需求收集通常能挖掘出大量你最初没想到的需求点"

## 🟡 建议改

### [Y1] CRDT/OT 对比表多处不严谨
- **位置**: 第 3.1 节 / 第 307-314 行
- **问题**:
  - "OT 需要中央服务器"是主流实现的概括，但 OT 理论上也可在客户端协调（如 Google Docs 早期实现），表述不够精确
  - "图形编辑器适配：优秀 vs 一般"是主观评价，缺乏客观标准
  - "生态成熟度：Yjs 成熟 vs ShareJS 较旧"选择性对比，OT 领域也有更现代实现（如 ot.js）
- **修改建议**: 增加脚注说明"OT 需要中央服务器"是主流工程实践的概括；将主观评价改为更具体的对比维度；补充 OT 的现代实现选项

### [Y2] CRDT 建模"很容易"过度简化
- **位置**: 第 3.1 节 / 第 321 行
- **问题**: 声称白板操作"在 CRDT 中很容易建模为 LWW 寄存器或计数器"
- **核实结果**: 图形编辑器中的位置（x, y）、大小、旋转角度、z-index 层级等属性需要更复杂的 CRDT 类型（如 LWW-Element-Set、Multi-Value Register、Map 等），而非简单的 LWW 寄存器或计数器
- **修改建议**: 将"很容易建模为 LWW 寄存器或计数器"改为"可以建模为 CRDT 数据结构（如 LWW-Map、MV-Register 等）"，并补充说明实际实现中的复杂性

### [Y3] 法律合规声明过于草率
- **位置**: 第 6.1 节 / 第 745-747 行
- **问题**: 在技术 PRD 中写"符合《个人信息保护法》要求"，将法律合规简化为 TLS + AES 技术配置
- **核实结果**: 《个人信息保护法》涉及数据收集最小化、用户同意、跨境传输限制、数据主体权利等多个维度，不是技术加密就能实现的
- **修改建议**: 改为"数据传输和存储需满足《个人信息保护法》的技术要求（加密、访问控制等），具体合规方案需咨询法律顾问"

### [Y4] 引用低质量 clickbait 来源
- **位置**: 第 1047-1066 行 / [^9]
- **问题**: 引用掘金文章标题"解决99%的需求混乱，让开发效率提升300%"，使用两个无数据支撑的精确百分比，是典型的 SEO clickbait 内容
- **修改建议**: 删除或替换该来源。如需保留，应在正文中降低其权重，明确标注为"社区经验分享"

## 📚 优点

1. **结构清晰，教学价值高**：从需求描述→功能拆解→架构设计→技术选型→文档产出→案例演示，形成完整的教学闭环

2. **对 Claude 局限性的讨论坦诚**：第 4 节详细讨论了隐含假设偏差、规模感知偏差、领域知识缺口和过度工程化风险，并提供了具体的防范策略

3. **对话示例丰富且实用**：大量的 `用户/Claude` 对话示例展示了真实的交互模式，读者可以直接模仿使用

4. **challenger 的部分质疑被证伪**：`/clear` 命令被官方 Best Practices 文档证实真实存在；OT 在主流实现中确实依赖中央服务器

5. **技术选型讨论有深度**：CRDT vs OT、Canvas 2D vs SVG 等对比虽然有不严谨之处，但总体方向正确，且提供了后续追问的示例（如"按视口订阅"的设计）

6. **文档模板可直接复用**：PRD、架构设计文档、API 设计文档的模板和示例具有实际参考价值
