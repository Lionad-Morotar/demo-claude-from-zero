# 修改建议:3.3-第一次代码变更

## 综合评估

- **整体质量**:这篇"第一次代码变更"文档是全书目前实用性最强的一章。它带领读者完整体验了从提出需求到确认修改的全过程，diff 阅读技巧、风险评估 checklist、权限模式详解、Checkpoint 回滚机制等内容都具有实际指导价值。核心功能描述（六种权限模式、Checkpoint 机制、安全架构）经核实全部准确。但 Auto Mode 部分存在多处细节错误："模型要求"将后台分类器模型误解为用户前台模型要求；`fileCheckpointingEnabled` 配置项疑似不存在；"100 个快照上限"和"仅限 Anthropic API"声明无官方来源。
- **问题分布**:🔴 高 5 项 / 🟡 中 5 项 / 🟢 低 2 项
- **建议处理优先级**:必改项涉及 Auto Mode 细节错误和疑似不存在的配置项，可能误导读者；建议改项涉及论述全面性和全书一致性。
- **是否阻塞发布**:否。核心功能描述准确，Auto Mode 细节错误不涉及严重安全问题，但建议在发布前修正。

## 🔴 必改(高优先级:事实错误、逻辑硬伤、严重误导)

### 1. Auto Mode "模型要求"将后台分类器误解为用户前台模型
- **位置**:第 3.5 节 / "使用条件"
- **原文摘录**:
  > "模型要求：Claude Sonnet 4.6、Opus 4.6 或 Opus 4.7"
- **问题**:官方博客确认 transcript classifier **运行在 Sonnet 4.6 上**，但并未声明用户必须使用 Sonnet 4.6、Opus 4.6 或 Opus 4.7 才能使用 Auto Mode。这是分类器后台模型，不是用户可选的前台模型。用户可以在 Auto Mode 下使用不同的 Claude 模型。
- **建议改写**:
  > "后台分类器：基于 Claude Sonnet 4.6 的独立分类器模型（非用户前台模型要求）"
- **依据**:[Anthropic Engineering Blog - Claude Code Auto Mode](https://www.anthropic.com/engineering/claude-code-auto-mode)

### 2. `fileCheckpointingEnabled: false` 配置项疑似不存在
- **位置**:第 6.5 节
- **原文摘录**:
  > "或在全局配置中设置 `fileCheckpointingEnabled: false`"
- **问题**:搜索 `fileCheckpointingEnabled` 在官方文档、GitHub、社区中**均无结果**。此配置项可能不存在，或是环境变量的错误对应。官方仅支持环境变量 `CLAUDE_CODE_DISABLE_FILE_CHECKPOINTING=1`。
- **建议改写**:删除此句，或改为"目前仅支持通过环境变量禁用，官方文档未提供配置项方式"。
- **依据**:[Claude Code Docs - Environment Variables](https://code.claude.com/docs/en/env-vars)

### 3. "仅限 Anthropic API"声明无官方来源
- **位置**:第 3.5 节 / "使用条件"
- **原文摘录**:
  > "提供商：仅限 Anthropic API，Bedrock/Vertex/Foundry 不支持"
- **问题**:Anthropic 官方博客和文档中**未提及 Auto Mode 的提供商限制**。无法证实此声明。此信息可能来自社区推断。
- **建议改写**:删除此条，或改为"提供商限制：官方文档未明确说明 Bedrock/Vertex/Foundry 是否支持 Auto Mode"。
- **依据**:verification 未找到官方支持

### 4. "最多保留 100 个快照"无官方来源
- **位置**:第 6.1 节
- **原文摘录**:
  > "最多保留 100 个快照，超出时淘汰最早的"
- **问题**:官方 Checkpointing 文档**未提及快照数量上限**。仅提到"30 天后自动清理（可配置）"。100 个上限可能是社区推断或过时信息。
- **建议改写**:删除"最多保留 100 个快照"，或改为"快照数量上限：官方文档未明确说明，实际可能受磁盘空间限制"。
- **依据**:[Claude Code Docs - Checkpointing](https://code.claude.com/docs/en/checkpointing)

### 5. Auto Mode 订阅限制时间线需澄清
- **位置**:第 3.5 节 / "使用条件"
- **原文摘录**:
  > "订阅计划：Max、Team、Enterprise 或 API。Pro 不可用"
- **问题**:官方发布时（2026 年 3 月）Auto Mode 作为 research preview **仅限 Team 计划**，Enterprise 和 API "coming in the coming days"。GitHub issue #39233 证实 Pro/Max 不可用。第三方来源 claudefa.st 声称 Max 可用，但与官方发布声明矛盾。文档将 Max 列入可用计划可能是基于后续更新，但原始发布时不包含 Max。
- **建议改写**:
  > "订阅计划：Team（原始发布时）、Enterprise 和 API（后续开放）。Pro 和 Max 最初不可用，Max 可能在后续更新中开放"
- **依据**:[Anthropic Engineering Blog](https://www.anthropic.com/engineering/claude-code-auto-mode)、[GitHub Issue #39233](https://github.com/anthropics/claude-code/issues/39233)

## 🟡 建议改(中优先级:论述方向、研究方法、表达冗余)

### 1. 权限模式数量全书不一致
- **位置**:第 3.1 节 / 模式对比总览
- **问题**:3.3 列出了 6 种权限模式（default、acceptEdits、plan、auto、dontAsk、bypassPermissions），与 1.6 和 3.1 一致。但 **1.2 说"七个级别"，1.5 说"五级"**。虽然 3.3 与 1.6/3.1 一致了，但全书范围内仍然矛盾。
- **建议**:全书统一为 6 种模式（以官方文档为准），并在各章节中统一命名和描述。在 1.2 和 1.5 中修正为 6 种。

### 2. Checkpoint Bash 限制的风险被低估
- **位置**:第 6.3 节
- **原文摘录**:
  > "Checkpoint **不追踪**以下变更：Bash 命令修改的文件（如 `rm file.txt`、`sed -i`）"
- **问题**:Bash 命令修改不可回滚是一个**重要的安全限制**——如果 Claude 通过 `sed -i` 或 `rm` 修改文件，用户无法回滚。文档虽然提到了这一点，但没有充分强调其风险，也没有提供缓解措施（如在使用 Bash 命令前手动备份）。
- **建议**:在 6.3 节增加一个警告框：
  > "⚠️ **重要警告**：Bash 命令修改的文件无法通过 `/rewind` 回滚。如果 Claude 执行了 `rm`、`sed -i`、`dd` 等命令，文件变更将永久生效。建议在使用 Bash 命令前手动 `git commit` 或手动备份关键文件。"

### 3. 频繁权限提示对开发流的负面影响讨论不足
- **位置**:第 2.1 节
- **问题**:文档将"修改前请求许可"描述为一种哲学性的安全设计（"AI 应该辅助人类决策，而非替代人类决策"），但对用户体验的负面影响讨论不足：频繁的权限提示会打断开发流（flow state），特别是在进行大规模重构时，逐次审批会显著降低效率。
- **建议**:在 2.1 节补充一段客观讨论：
  > "当然，频繁的权限提示也有其代价——它会打断开发流（flow state），特别是在进行大规模重构时，逐次审批可能显著降低效率。这就是为什么 Claude Code 提供了 Accept Edits 和 Auto Mode 等更宽松的模式，让你在信任建立后逐步减少中断。"

### 4. `~/.claude/file-history/` 精确路径未获官方确认
- **位置**:第 6.1 节
- **原文摘录**:
  > "存储位置：`~/.claude/file-history/{sessionId}/`"
- **问题**:仅 Zenn 社区文章提及此路径，**官方文档未明确确认**。`file-history/` 更像是内部实现细节，可能随时变更。
- **建议**:改为"存储位置：`~/.claude/` 下的内部目录（具体路径可能随版本变化，官方文档未公开确认）"。

### 5. `/rewind` 交互式菜单选项数与官方描述有出入
- **位置**:第 6.2 节
- **原文摘录**:
  > "四种回滚方式"
- **问题**:官方文档确认 `/rewind` 提供 **五种选项**：Restore code and conversation、Restore conversation、Restore code、Summarize from here、Never mind。文档说"四种"，遗漏了 "Summarize from here"（或将其归类为"从此处总结"但未计入回滚方式）。
- **建议**:改为"五种选项"，并在表格中加入 "Summarize from here | 不变 | 压缩 | 上下文窗口满了，需要释放空间"。
- **依据**:[Claude Code Docs - Checkpointing](https://code.claude.com/docs/en/checkpointing)
