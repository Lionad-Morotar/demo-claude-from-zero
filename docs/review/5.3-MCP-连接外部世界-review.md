# 修改建议: 5.3 MCP——通过模型上下文协议连接外部世界

## 综合评估
- 整体质量: 核心概念（MCP 架构、JSON-RPC 2.0、三种原语、生命周期）与 modelcontextprotocol.io 官方文档基本一致。但安装配置和生态描述存在较多未验证细节
- 问题分布: 🔴 高 3 / 🟡 中 6 / 🟢 低 3
- 是否阻塞发布: 否（修正配置路径 + 删除/标注未验证命令后可发布）

## 🔴 必改(高优先级:事实错误、逻辑硬伤)

### 1. `~/.claude.json` 路径错误
- **位置**: 第 4.2 节 / 配置作用域表
- **原文摘录**:
  | **Local**（默认） | 仅当前项目 | 否 | `~/.claude.json` |
  | **User** | 所有项目 | 否 | `~/.claude.json` |
- **问题**: Local 和 User 指向同一文件 `~/.claude.json`，但描述分别为"仅当前项目"和"所有项目"，逻辑矛盾。官方实际使用 `~/.claude/settings.json`（user 级）和 `.claude/settings.json`（project 级），不是 `.claude.json`。
- **建议改写**:
  | 作用域 | 加载范围 | 团队共享 | 存储位置 |
  |--------|---------|---------|---------|
  | **Project** | 仅当前项目 | 是 | `.claude/settings.json` |
  | **User** | 所有项目 | 否 | `~/.claude/settings.json` |
- **依据**: https://code.claude.com/docs/en/setup（web-searcher 核实）

### 2. `@bytebase/dbhub` 包不存在
- **位置**: 第 4.5 节 / PostgreSQL 配置示例
- **原文摘录**:
  ```bash
  claude mcp add --transport stdio db -- npx -y @bytebase/dbhub
  ```
- **问题**: npm 搜索未找到 `@bytebase/dbhub` 包。PostgreSQL 官方 MCP Server 是 `@modelcontextprotocol/server-postgres`。
- **建议改写**:
  ```bash
  claude mcp add --transport stdio db -- npx -y @modelcontextprotocol/server-postgres \
    "postgresql://readonly:pass@prod.db.com:5432/analytics"
  ```
- **依据**: web-searcher 核实，npm 搜索无 `@bytebase/dbhub`

### 3. `isError: true` 返回值未获官方确认
- **位置**: 第 5.3 节 / 工具实现代码
- **原文摘录**:
  ```typescript
  return {
    content: [{ type: "text", text: "查询失败..." }],
    isError: true,
  };
  ```
- **问题**: MCP 协议中 tool 返回错误通常通过抛出异常或返回特定错误格式，而非在结果对象中设置 `isError` 字段。该字段未在 MCP SDK 官方类型定义中确认。
- **建议改写**: 删除 `isError: true`，改用抛出异常的方式：
  ```typescript
  } catch (error) {
    throw new Error(`查询失败：${error instanceof Error ? error.message : '未知错误'}`);
  }
  ```
- **依据**: web-searcher 未找到官方确认

## 🟡 建议改(中优先级)

### 4. `claude mcp add` 命令语法未完全确认
- **位置**: 第 4.1 节
- **原文摘录**:
  ```bash
  claude mcp add --transport http <name> <url>
  claude mcp add --transport sse <name> <url>
  claude mcp add [options] <name> -- <command> [args...]
  ```
- **问题**: 官方 CLI 参考确认 `claude mcp` 命令存在，但未明确列出 `add` 子命令的具体语法。`--transport http` 等具体语法需要官方文档进一步确认。
- **建议改写**: 在命令示例前添加注释：

  并提供 `settings.json` 配置方式作为替代方案。
- **依据**: https://code.claude.com/docs/en/cli-reference（web-searcher 核实，`claude mcp` 存在但 `add` 子命令语法未详细列出）

## 🟢 可选改(低优先级)

### 10. "17000+ Server"可能是营销数字
- **位置**: 第 3.3 节
- **原文摘录**: "[MCPpedia](https://mcppedia.org/) — 17000+ Server 的安全评分和比较"
- **问题**: "17000+"这个数字极可能是该网站自我宣传的数字，实际 MCP Server 生态远未达到这个规模。
- **建议改写**: "[MCPpedia](https://mcppedia.org/) — MCP Server 目录（含安全评分）"
- **依据**: challenger [C]

### 11. Function Call 对比表有失偏颇
- **位置**: 第 6.1 节
- **原文摘录**:
  | **依赖关系** | 深度绑定特定模型 | 模型无关（兼容 Claude/GPT/通义等） |
  | **跨设备调用** | 限于本地环境 | 支持远程/云工具调用 |
- **问题**: Function Call（如 OpenAI 的 tools 格式）已被多个模型和平台支持，且可以调用远程 API，不限于本地。这种对比是为了抬高 MCP 而贬低 Function Call。
- **建议改写**: 将"深度绑定特定模型"改为"最初由特定模型提出，现已被多平台采纳"；将"限于本地环境"改为"通常由宿主应用直接处理"。
- **依据**: challenger [A]

### 12. "MCP 正在成为企业 AI 基础设施的事实标准协议"过于绝对
- **位置**: 第 6.4 节
- **原文摘录**: "MCP 正在成为企业 AI 基础设施的事实标准协议"
- **问题**: "事实标准"意味着已经广泛采纳，而 MCP 目前仍处于早期推广阶段。
- **建议改写**: "MCP 正在发展成为 AI 工具连接的重要协议标准之一"
- **依据**: challenger [B]
