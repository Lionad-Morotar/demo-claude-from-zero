# 修改建议:3.2-让-Claude-理解你的项目

## 综合评估

- **整体质量**:文档提供了大量实用的提问模板和代码库理解策略，对初学者有一定参考价值。提问模板（"探索-计划-编码"框架、精确提问公式）和大型代码库处理策略（"放大-缩小"工作流、外科手术式上下文加载）都是合理的工程实践建议。但存在严重问题：**`.claudeignore` 是虚构功能**——文档第 7.6 节基于一个不存在的功能提供了完整的使用指南；Subagent 模型分配不准确；CLAUDE.md 加载规则被过度简化为"优先级覆盖"。
- **问题分布**:🔴 高 3 项 / 🟡 中 8 项 / 🟢 低 2 项
- **建议处理优先级**:必改项涉及虚构功能和错误机制描述，将直接误导读者；建议改项涉及来源质量和论述全面性。
- **是否阻塞发布**:是。`.claudeignore` 是虚构功能，7.6 节全部内容基于幻觉，若不修正将严重损害整本书的可信度。

## 🔴 必改(高优先级:事实错误、逻辑硬伤、严重误导)

### 1. `.claudeignore` 是虚构功能——最严重事实错误
- **位置**:第 7.6 节 / 全部内容
- **原文摘录**:
  > "类似于 `.gitignore`，你可以创建 `.claudeignore` 文件来告诉 Claude Code 忽略某些文件和目录"
- **问题**:`.claudeignore` **并非 Claude Code 的真实功能**。The Register 安全报告 (2026-01-28) 明确指出：当用户问".env 如何阻止读取"时，Claude 会幻觉回答"使用 .claudeignore"，但这是错误的——Claude Code 实际上会读取 `.env` 文件。GitHub issue #579 (feature request) 和 #2305 均为请求添加 `.claudeignore` 功能，说明该功能**尚未实现**。Stack Overflow 上亦有开发者报告该功能请求被"反复拒绝"。文档第 7.6 节基于一个不存在的功能提供了完整的使用指南，这可能源于 Claude 自身的幻觉输出被作者采信。
- **建议改写**:
  > "Claude Code 目前**不支持** `.claudeignore` 功能（Anthropic 已反复拒绝相关功能请求，见 GitHub issue #579）。如需限制 Claude 读取特定文件，应使用 `permissions.deny` 规则配置。"
- **依据**:[The Register - Claude Code AI secrets files](https://www.theregister.com/2026/01/28/claude_code_ai_secrets_files/)、[GitHub Issue #579](https://github.com/anthropics/claude-code/issues/579)

### 2. Subagent 模型分配不准确
- **位置**:第 3.4 节 / Subagent 的三种类型表格
- **原文摘录**:
  > "General-purpose | Sonnet | 读写""Plan | Sonnet | 只读"
- **问题**:General-purpose 和 Plan **并非固定使用 Sonnet**，而是 **inherits model**（继承主会话模型）。这意味着如果用户在 Opus 4.7 模式下调用 Plan subagent，Plan 也会使用 Opus 4.7，而非固定使用 Sonnet。只有 Explore 是固定使用 Haiku（快速、低成本）。
- **建议改写**:
  > "General-purpose | 继承主会话模型 | 读写""Plan | 继承主会话模型 | 只读"
- **依据**:[morphllm.com - Claude Code Subagents](https://morphllm.com)

### 3. CLAUDE.md 加载规则被过度简化为"优先级覆盖"
- **位置**:第 5.3 节
- **原文摘录**:
  > "加载优先级：子目录 > 项目根 > 全局"
- **问题**:官方机制并非简单的"优先级覆盖"，而是：① 父目录 CLAUDE.md 在**启动时**加载（eager scan）；② 子目录 CLAUDE.md 在**访问该目录时按需加载**（on-demand）。实际是**合并/叠加**机制，而非覆盖。1.5 说的"加载所有"和 3.2 说的"优先级"都不完全准确。
- **建议改写**:
  > "加载机制：父目录的 CLAUDE.md 在启动时自动加载；当你访问子目录时，该子目录的 CLAUDE.md 会按需加载。多个 CLAUDE.md 的内容会合并到系统提示中，而非相互覆盖。"
- **依据**:[Claude Code Docs](https://code.claude.com/docs/en/claude-md)、[GitHub Issue #6972](https://github.com/anthropics/claude-code/issues/6972)

## 🟡 建议改(中优先级:论述方向、研究方法、表达冗余)

### 1. 上下文窗口占比数字无官方来源
- **位置**:第 4.1 节 / 表格
- **原文摘录**:
  > "系统提示和 CLAUDE.md | ~5-10%""用户消息 | ~10-15%""Claude 的响应 | ~25-35%""文件读取 | ~20-30%"
- **问题**:这些占比数字是作者估算，**未找到 Anthropic 官方文档提供此类固定百分比**。实际占比因任务、模型、配置差异极大。社区估算 vary widely：morphllm.com 称系统开销约 30-40K tokens（在 200K 窗口中约 15-20%），与文档的 ~5-10% 差距较大。在 1M 窗口模型上，同样的系统开销占比会大幅下降。
- **建议**:在表格下方添加免责声明："上述占比为示例估算，实际占比因模型选择（200K vs 1M 窗口）、MCP 工具数量、CLAUDE.md 长度等因素差异极大。"

### 2. "文件选择优先级算法"无官方来源
- **位置**:第 1.3 节
- **原文摘录**:
  > "Claude Code 内置了一套文件选择优先级算法""优先级 1：显式提及的文件""优先级 2：与问题语义相关的文件"...
- **问题**:未找到 Anthropic 官方文档描述此类固定优先级算法。Claude Code 的文件选择行为更可能是基于 LLM 推理的动态决策，而非硬编码的优先级规则。这很可能是作者基于观察自行归纳的启发式规则。
- **建议**:将标题改为"文件选择行为模式（观察到的启发式规则）"，并在段落开头添加："以下优先级基于对 Claude Code 行为的观察总结，非官方文档确认的固定算法。实际行为可能因任务和模型版本而异。"

### 3. 缺少 CLAUDE.md 局限性的讨论
- **位置**:第 5.1 节
- **问题**:文档大力推崇 CLAUDE.md 作为"最重要的上下文机制"，但未讨论其局限性：① CLAUDE.md 内容也占用上下文窗口；② 过长的 CLAUDE.md 可能导致注意力稀释；③ CLAUDE.md 中的错误指令会被每个会话重复执行；④ 多层级 CLAUDE.md 可能导致指令冲突。
- **建议**:在 5.1 节末尾增加"CLAUDE.md 的局限性"小节，讨论上述问题。

### 4. "预期响应"示例的理想化
- **位置**:分布全文（2.1、2.2、2.3、3.2、3.3、4.3、6.1 等节）
- **问题**:文档中大量使用了"预期响应"示例，展示 Claude Code 的理想输出。但这些示例是文档作者编写的理想化输出，不代表 Claude Code 的实际输出质量。Claude 的实际输出可能因模型版本、上下文长度、任务复杂度而有很大差异。
- **建议**:在首次出现"预期响应"示例的位置添加统一免责声明："以下示例为理想化输出，实际输出可能因模型版本、上下文长度和任务复杂度而有所不同。"

### 5. "30 分钟理解项目"过度简化
- **位置**:第 8 节 / 最后 1 段
- **原文摘录**:
  > "你可以在 30 分钟内建立起对一个陌生中大型项目的系统性理解，而传统方式可能需要数天"
- **问题**:这是一个过度简化的对比。项目理解的深度取决于项目的复杂度、开发者的领域知识和 Claude Code 的上下文限制。对于高度复杂的领域（如金融核心系统、嵌入式固件），30 分钟的理解可能非常浅薄。
- **建议**:改为"对于结构清晰、文档完善的中型 Web 项目，你可以在 30 分钟内建立起初步的系统性理解框架。但深度理解仍需结合领域知识和持续探索。"

### 6. "放大-缩小"工作流和上下文预算心智模型应标注为作者建议
- **位置**:第 7.2-7.3 节
- **问题**:"放大-缩小"工作流和"上下文预算心智模型"是文档作者自行总结的方法论，虽然有价值，但应明确标注为作者建议而非官方推荐的工作流。
- **建议**:在 7.2 节开头添加："以下'放大-缩小'工作流是作者基于实践经验总结的工程方法，非 Claude Code 官方文档推荐的标准工作流。"

### 7. 引用来源权威性不足
- **位置**:分布全文
- **问题**:大量引用个人博客和小型网站：Nate Ross、eesel.ai、Kane.mx、Osvaldo Restrepo、Iceberg Lakehouse、Ralphable、Hashbuilds、AGI In Progress、CometAPI。这些来源的权威性不足。
- **建议**:优先使用 Anthropic 官方文档替代个人博客引用。对于无法找到官方来源的内容，标注为"社区经验分享"。

### 8. `/context` 输出应标注为近似值
- **位置**:第 4.3 节
- **原文摘录**:
  > "Context usage: 68% (142,000 / 200,000 tokens)"
- **问题**:Claude Code 官方确认 `/context` 显示的是 "approximation of your context usage"（近似值），非精确 token 计数。
- **建议**:在示例输出下方添加："注：/context 显示的是上下文使用的近似值，非精确 token 计数。"
- **依据**:[claudelog.com](https://claudelog.com)
