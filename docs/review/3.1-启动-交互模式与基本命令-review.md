# 修改建议:3.1-启动-交互模式与基本命令

## 综合评估

- **整体质量**:这是全书目前事实核查命中率最高的一章。经逐一核对官方 Commands 文档，约 40 个斜杠命令中**绝大多数都真实存在**（包括 `/btw`、`/loop`、`/schedule`、`/teleport`、`/recap`、`/desktop`、`/chrome`、`/security-review`、`/simplify` 等），令人惊讶。所有 CLI 参数、环境变量、快捷键、高级功能（会话回顾、PR 状态、图片粘贴）均确认存在。文档内容极其丰富，结构清晰，作为命令参考手册具有很高的实用价值。
- **问题分布**:🔴 高 2 项 / 🟡 中 4 项 / 🟢 低 2 项
- **建议处理优先级**:必改项涉及 `/btw` 的重要限制未说明和 `/vim` 命令已移除；建议改项涉及论述准确性和全书一致性。
- **是否阻塞发布**:否。核心技术细节几乎全部准确，仅需修正少数细节。

## 🔴 必改(高优先级:事实错误、逻辑硬伤、严重误导)

### 1. `/btw` 没有工具访问权限——文档未提及此重要限制
- **位置**:第 4.5 节
- **原文摘录**:
  > "问一个快速旁支问题，不加入对话历史。低成本、无工具访问"
- **问题**:官方文档明确说明 `/btw` **"No tool access: side questions answer only from what is already in context"**。Claude 不能读取文件、运行命令或搜索。文档虽然写了"无工具访问"，但未充分强调其限制——读者可能误以为 `/btw` 可以旁支查询文件内容，实际上它只能基于已有上下文回答。
- **建议改写**:
  > "问一个快速旁支问题，不加入对话历史。低成本，但**只能基于已有上下文回答，无法访问工具、读取文件或运行命令**"
- **依据**:[Claude Code Docs: Interactive mode](https://code.claude.com/docs/en/interactive-mode)

### 2. `/vim` 命令已移除——需更新为新的启用方式
- **位置**:第 8 节 / Vim 编辑模式
- **原文摘录**:
  > "通过 `/vim` 启用 Vim 风格输入模式"
- **问题**:官方 Commands 文档明确标注 `"Removed in v2.1.92. To toggle between Vim and Normal editing modes, use /config → Editor mode"`。如果文档中引用了 `/vim` 命令（速查卡中也可能存在），需要更新为新的启用方式。
- **建议改写**:
  > "通过 `/config` → Editor mode 启用 Vim 风格输入模式（`/vim` 命令已在 v2.1.92 中移除）"
- **依据**:[Claude Code Docs: Commands](https://code.claude.com/docs/en/commands)

## 🟡 建议改(中优先级:论述方向、研究方法、表达冗余)

### 1. Vim 模式不支持块选择 (Ctrl+V)
- **位置**:第 8 节
- **原文摘录**:
  > "Claude Code 提供了完整的 Vim 风格输入模式"
- **问题**:官方 Interactive mode 文档明确 **"Block-wise visual mode with Ctrl+V is not supported"**。如果文档声称支持"完整的"Vim 风格输入模式，这一说法可能过于夸大。
- **建议改写**:
  > "Claude Code 提供了 Vim 风格输入模式，支持 Normal、Insert、Visual 模式及文本对象（iw, aw, i\", a\", i(, a( 等）。注意：Block-wise visual mode (Ctrl+V) 不支持。"
- **依据**:[Claude Code Docs: Terminal config](https://code.claude.com/docs/en/terminal-config)

### 2. "五分钟内从完全新手成长为熟练用户"过度承诺
- **位置**:开篇
- **原文摘录**:
  > "目标是让你在五分钟内从完全新手成长为能够流畅驾驭 Claude Code 的熟练用户"
- **问题**:这是一个过度承诺。Claude Code 的学习曲线（特别是权限模式理解、上下文管理、工具使用）实际上相当陡峭，五分钟只能学会基本启动和退出，远不能达到"流畅驾驭"的水平。
- **建议改写**:
  > "目标是在五分钟内帮助你掌握 Claude Code 的启动、基本命令和交互模式，为后续深入学习打下基础。"

### 3. 权限模式数量全书不一致
- **位置**:第 5.2 节
- **问题**:3.1 的权限模式命名终于与 1.6 一致（6 种：default、acceptEdits、plan、auto、dontAsk、bypassPermissions），但 **1.2 说"七个级别"，1.5 说"五级"，2.3 说"四级"**。作为系统性教程，同一产品的核心功能在不同章节中出现多种不同的数量和命名方式，这是不可接受的。
- **建议**:全书统一为 6 种模式（以官方文档为准），在各章节中统一命名和描述。在 1.2 和 1.5 中修正为 6 种。

### 4. 欢迎界面的 ASCII 示意图是作者自行绘制
- **位置**:第 2.1 节
- **问题**:文档中的 ASCII 欢迎界面示意图是作者自行绘制的，可能不完全反映真实界面布局。虽然核心信息（版本、模型、项目路径、Git 状态、最近会话）经确认是准确的，但具体布局可能与实际有差异。
- **建议**:在示意图下方添加说明："以上为示意图，实际界面布局可能略有不同。"
