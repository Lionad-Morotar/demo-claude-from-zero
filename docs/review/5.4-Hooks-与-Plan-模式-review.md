# Review: 5.4-Hooks-与-Plan-模式.md

## 🔴 必改

### [R1] 生命周期事件数量错误（最严重的事实错误）
- **位置**: 第 1.2 节 / 第 20 行
- **问题**: 声称"截至 2026 年 3 月，Claude Code 支持 21 个生命周期事件"，但实际列出 22 个，且官方文档至少列出 24 个
- **核实结果**: 遗漏了 `UserPromptExpansion` 和 `PermissionDenied` 两个官方事件。`TeammateIdle`、`Elicitation`、`ElicitationResult` 等被质疑的事件均为真实存在
- **修改建议**: 修正为"截至 2026 年 3 月，Claude Code 支持至少 24 个生命周期事件"，并补充 `UserPromptExpansion`（用户提示扩展时）和 `PermissionDenied`（权限请求被拒绝时）到事件列表

### [R2] Hooks JSON 配置格式与官方不符
- **位置**: 第 1.4 节 / 第 90-116 行
- **问题**: 配置示例使用 `"hooks": { "PreToolUse": [{ "matcher": "Bash", "hooks": [...] }] }` 结构，内层 `"hooks"` 数组与外层 `"hooks"` 键同名，造成层级混淆
- **核实结果**: 官方标准格式为 `"hooks": { "EventName": [{ "matcher": "...", "command": "..." }] }`，**没有内层 `"hooks"` 数组**
- **修改建议**: 统一全书 Hooks JSON 格式，删除内层 `"hooks"` 键，改为官方标准格式。例如：
  ```json
  {
    "hooks": {
      "PreToolUse": [
        {
          "matcher": "Bash",
          "command": "echo \"$CLAUDE_TOOL_INPUT\" | grep -qE 'rm -rf|DROP TABLE' && exit 2 || exit 0"
        }
      ]
    }
  }
  ```

### [R3] Esc+Esc 功能与 4.4 章严重矛盾
- **位置**: 第 6.2 节 / 第 587 行；4.4 章 / 第 98 行
- **问题**: 4.4 章（Git 工作流）称 Esc+Esc 是"撤销所有正在进行的修改"；5.4 章称 Esc+Esc 是"打开恢复菜单"
- **核实结果**: 官方 Checkpointing 文档明确说明 Esc+Esc 用于 `/rewind` 菜单。**5.4 章正确，4.4 章错误**
- **修改建议**: 4.4 章需要修正 Esc+Esc 的描述，全书需统一为"打开恢复菜单（rewind）"。5.4 章可在本节添加注释说明 Esc+Esc 的确切功能，避免读者被 4.4 章误导

## 🟡 建议改

- **位置**: 第 1.5 节 / 第 137-139 行

### [Y4] 全书 Hooks JSON 格式不统一

## 🟢 可选改

### [G1] "确定性"表述过度承诺
- **位置**: 第 1.1 节 / 第 14 行
- **问题**: 将 Hooks 描述为"确定性"的——"只要事件触发，Hook 就一定会执行"。但 Hook 是 shell 命令，可能因环境、路径、依赖缺失而失败
- **修改建议**: 改为"Hooks 是强制执行的——事件触发时 Claude Code 会尝试执行 Hook，但 shell 脚本本身可能因环境原因失败"，更准确且不过度承诺

### [G2] 分类器性能数据应标注来源
- **位置**: 第 5.4 节 / 第 496-500 行
- **问题**: Stage 1 FPR 8.5% 但完整管道 FPR 0.4%，21 倍改善仅用 Stage 2 链式思考实现，读者可能质疑其可信度
- **修改建议**: 数据已证实准确（来自 Anthropic 官方工程博客），建议在表格下方添加脚注标注数据来源，如"数据来源：Anthropic 官方工程博客 'Claude Code Auto Mode'"
