# 修改建议:2.3-选择你的界面

## 综合评估

- **整体质量**:这是全书目前事实核查命中率最高的章节之一。经逐一核实，几乎所有 CLI 命令、参数、VS Code 扩展 ID、JetBrains 插件 ID、桌面应用功能、Slack 集成、GitHub Actions 等均真实存在。TechCrunch 报道的发布时间也准确。文档提供了全面的七界面对比矩阵，对初学者选择合适界面有实际参考价值。

## 🔴 必改(高优先级:事实错误、逻辑硬伤、严重误导)

### 1. 网页版 VM 规格无官方来源
- **位置**:第 5.4 节
- **原文摘录**:
  > "每个会话运行在独立的 Ubuntu 24.04 VM 中""资源限制：4 vCPU / 16 GB RAM / 30 GB 磁盘"
- **问题**:官方文档提到 "Anthropic-managed VM" 但未公布具体硬件规格和操作系统版本。"4 vCPU / 16 GB / 30 GB" 和 "Ubuntu 24.04" 这两个具体数字**未找到 Anthropic 官方文档确认**，可能来自社区观察或推断。
- **建议改写**:
  > "每个会话运行在 Anthropic 管理的云端 VM 中（具体硬件规格官方未公开）"
- **依据**:verification 未找到官方来源

### 2. `mcp__gitlab` 工具名格式错误
- **位置**:第 7.2 节 / GitLab CI/CD 配置
- **原文摘录**:
  > `--allowedTools "Bash Read Edit Write mcp__gitlab"`
- **问题**:MCP 工具的正确命名格式是 `mcp__<server>__<tool>`（双下划线分隔服务器名和工具名）。文档中的 `mcp__gitlab` 缺少第二层工具名。正确的写法可能是 `mcp__gitlab__*`（通配）或具体的工具名如 `mcp__gitlab__mcp_gitlab_server`。
- **建议改写**:
  > `--allowedTools "Bash Read Edit Write mcp__gitlab__*"`
- **依据**:[Claude Code Docs: Permissions](https://code.claude.com/docs/en/permissions)

### 3. 权限模式数量遗漏 acceptEdits
- **位置**:第 1.3 节 / 核心功能表格 + 第 1.4 节
- **原文摘录**:
  > "权限模式 | 默认 / 计划 / 自动 / 绕过权限 四级控制"
  > "默认 → 计划 → 自动 → 绕过权限"
- **问题**:官方确认权限模式有 6 种（default、acceptEdits、plan、auto、dontAsk、bypassPermissions）。2.3 的 1.3 节和 1.4 节**遗漏了 acceptEdits 和 dontAsk**，只列出 4 种。虽然 8.2 节补全了 6 种，但使用了 UI 显示名称而非内部名称，与 1.6/3.1 的内部命名不一致。
- **建议改写**:
  > "权限模式 | default / acceptEdits / plan / auto / dontAsk / bypassPermissions 六级控制"
  > "default → acceptEdits → plan → auto → dontAsk → bypassPermissions"
- **依据**:[Claude Code Docs: Permissions](https://code.claude.com/docs/en/permissions)

## 🟡 建议改(中优先级:论述方向、研究方法、表达冗余)

### 1. Cursor 扩展安装语法未验证
- **位置**:第 2.2 节
- **原文摘录**:
  > "也支持 Cursor：cursor:extension/anthropic.claude-code"
- **问题**:`cursor:extension/...` 语法**未找到任何官方或社区来源支持**。Cursor 基于 VS Code 但有自己的扩展市场机制，此语法可能不存在。
- **建议**:删除此句，或改为"Cursor 用户可在 Cursor 扩展市场中搜索并安装 Claude Code 扩展"。

### 2. `claude -r` 带提示词的语法存疑
- **位置**:第 1.4 节
- **原文摘录**:
  > `claude -r "auth-refactor" "Finish this PR"`
- **问题**:官方 CLI 参考中 `--resume` 的示例是 `claude --resume auth-refactor`，**未展示在恢复会话的同时传递提示词的用法**。`claude -r <session> "prompt"` 的语法需要进一步验证。
- **建议**:删除第二个参数示例，或改为"`claude -r "auth-refactor"` 恢复指定会话，恢复后可继续输入新指令"。

### 3. 权限模式命名全书不一致
- **位置**:第 8.2 节
- **问题**:8.2 节使用了 UI 显示名称（Ask permissions、Auto accept edits、Plan mode、Auto mode、Bypass permissions、dontAsk），而 1.6/3.1 使用内部名称（default、acceptEdits、plan、auto、bypassPermissions、dontAsk）。虽然数量一致（6 种），但命名不统一会让读者困惑。
- **建议**:在 8.2 节表格中同时标注内部名称，如"Ask permissions（default）""Auto accept edits（acceptEdits）"等。

### 4. "计划审查"和"计划模式"表述可能混淆
- **位置**:第 2.3 节 + 第 3.7 节
- **问题**:2.3 节的 VS Code 扩展功能列表中有"计划审查"，3.7 节说 JetBrains 插件"缺少计划审查等高级功能"，但 8.1 节功能对比表格显示 JetBrains 在"计划模式"上是"支持"。"计划审查"和"计划模式"是否是同一功能？文档的表述存在矛盾。
- **建议**:统一术语。如果"计划审查"是 VS Code 扩展特有的功能（计划以 Markdown 文档形式展示），应在功能对比表格中单独列出；如果与"计划模式"是同一功能，应统一命名。
