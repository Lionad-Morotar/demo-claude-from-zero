# Review: 7.1-提示词设计原则.md

## 事实准确性

### [1] "能力天花板/上限"表述 — 需要修改
- **原文**: "能力天花板由 Anthropic 决定，但用户实际拿到的能力上限由你的提示词决定"
- **问题**: 经核实，Anthropic 官方文档中不存在此原文表述，属于作者观点被包装为引用。
- **建议**: 删除引号，改为作者本人观点，如"在实践中，提示词质量对输出效果有显著影响"。

### [2] "同一个 Claude Opus，在专业用户和新手手里，产出的代码质量差距可能高达数倍" — 需要修改
- **原文**: "产出的代码质量差距可能高达数倍"
- **问题**: "数倍"差距无任何量化依据，属于推测性修辞。
- **建议**: 删除"数倍"精确数字，改为定性描述"显著差距"。

### [3] XML 标签推荐 — 部分修改
- **原文**: "明确推荐"使用 `<output_format>` 标签
- **核实**: 官方文档确实强烈推荐 XML 标签（用词"game-changer"），但官方示例标签为 `<instructions>`、`<example>`、`<formatting>`，**未出现** `<output_format>`。
- **建议**: 将 `<output_format>` 改为官方示例标签（如 `<formatting>` 或 `<instructions>`），或注明为自定义标签示例。

### [4] "30%"复述暴露率 — 需要修改
- **原文**: "约 30% 的复述会暴露需求歧义"
- **问题**: 纯个人轶事，无方法论支撑。
- **建议**: 删除"30%"精确数字，改为"在我个人经验中，相当比例的复述会暴露需求歧义"。

### [5] Plan Mode `Shift+Tab` 切换 — 基本正确，建议补充
- **核实**: `Shift+Tab` 确实用于 cycle permission modes，但官方说明是从 Normal → Auto-Accept → Plan，可能需要按两次。
- **建议**: 补充说明"通过 Shift+Tab 在权限模式间循环切换（可能需要按两次到达 Plan Mode）"。

### [6] ">100K tokens" 阈值 — 需要修改
- **原文**: 建议上下文超过 100K 时开启新会话
- **问题**: 官方未推荐此阈值。Claude Code 标准上下文为 200K，Opus/Sonnet 4.6+ 支持 1M。
- **建议**: 删除"100K"阈值，改为"当上下文堆积过多无关内容时，使用 `/clear` 重置会话"。

### [7] "训练数据中英文比例较高" — 需要修改
- **问题**: Anthropic 未公开训练数据的语言比例构成。
- **建议**: 改为"据推测，英文在训练数据中占比较高"，或删除该句。

### [8] 情绪化前缀研究 — 需要补充引用
- **原文**: "早期一些研究确实发现某些情绪化前缀能轻微提升表现"
- **核实**: 相关研究存在（EmotionPrompt 2023、arXiv:2604.02236v1 等），但原文未提供任何引用。
- **建议**: 补充具体引用，并弱化"轻微提升"为"在特定任务类型上可能有微弱影响"。

### [9] Claude Code 多模态输入 — 基本正确，建议补充
- **核实**: 图片输入（粘贴/拖拽/文件路径）官方确认；PDF 支持通过文件路径读取。
- **建议**: 补充具体输入方式，避免读者误以为支持终端内直接拖放。

### [10] Boris Cherny 身份 — 措辞可更精确
- **原文**: "Claude Code 作者"
- **核实**: 权威来源称其为 "creator and Head of Claude Code at Anthropic"。
- **建议**: 改为"Claude Code 创建者/负责人（Creator & Head）"。

### [G] 编号错误 — 直接修正
- **问题**: 4.6 → 4.7 → 4.5 的顺序错乱
- **建议**: 修正为 4.5 → 4.6 → 4.7。

## 引用格式

- 第 8 条建议使用的引用格式（`[^1^]` 风格）与本书其他章节使用的标准 Markdown 脚注风格不一致，需统一。

## 总体评价

本章核心概念（XML 标签、Plan Mode、多模态输入）基本正确，但存在多处将个人观点包装为官方论述的问题，以及缺乏来源的量化数字。修改后可信度将显著提升。
