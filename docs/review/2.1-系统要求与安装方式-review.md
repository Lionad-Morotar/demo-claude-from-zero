# 修改建议: 2.1 系统要求与安装方式（macOS / Windows / Linux）

## 综合评估
- 整体质量: 引用准确度极高，官方文档几乎完全支持全部事实声明。结构清晰，覆盖三大平台，FAQ实用
- 问题分布: 🔴 高 2 / 🟡 中 3 / 🟢 低 2
- 是否阻塞发布: 否（修正高优先级后可发布）

## 🔴 必改(高优先级:事实错误、逻辑硬伤)

### 1. `@musistudio/claude-code-router` npm 包不存在
- **位置**: 第 5.2 节 / 路线 B
- **原文摘录**: 
  ```bash
  npm install -g @musistudio/claude-code-router
  ```
- **问题**: 该 npm 包在 npm registry 中不存在，搜索无结果。文档将其作为"国产模型替代方案"推荐，读者执行该命令会直接失败。
- **建议改写**: 删除该包引用，替换为真实存在的开源工具（如 zenmux、openrouter 等），或改为通用描述："使用开源 router 工具（如 openrouter 等）将请求转发给硅基流动、DeepSeek 等国内模型服务。"
- **依据**: https://www.npmjs.com/search?q=%40musistudio%2Fclaude-code-router（web-searcher 核实，无结果）

### 2. `ANTHROPIC_AUTH_TOKEN` 变量值类型错误
- **位置**: 第 5.2 节 / 路线 A
- **原文摘录**: 
  ```json
  {
    "env": {
      "ANTHROPIC_AUTH_TOKEN": "sk-your-api-key",
      "ANTHROPIC_BASE_URL": "https://your-router-domain.com"
    }
  }
  ```
- **问题**: `ANTHROPIC_AUTH_TOKEN` 确实存在（与 `ANTHROPIC_API_KEY` 并存），但 **AUTH_TOKEN 应接受 bearer token（如 OAuth token），而非 `sk-` 前缀的 API key**。`sk-your-api-key` 是 API key 格式，应放入 `ANTHROPIC_API_KEY` 变量。文档混淆了两种认证方式的值类型。
- **建议改写**: 
  ```json
  {
    "env": {
      "ANTHROPIC_API_KEY": "sk-your-api-key",
      "ANTHROPIC_BASE_URL": "https://your-router-domain.com"
    }
  }
  ```
  或如需使用 AUTH_TOKEN，应说明其接受 bearer token 格式而非 API key。
- **依据**: https://code.claude.com/docs/en/env-vars（web-searcher 核实，官方文档区分两种变量）

## 🟡 建议改(中优先级)

### 3. Teams 定价标注不清导致跨文档矛盾
- **位置**: 第 1.4 节 / 账户要求表格
- **原文摘录**: 
  | Teams Standard | $25/人/月 | 小型团队 |
- **问题**: 与 1.1/1.3 的 "Teams $150/用户/月" 相差 6 倍。经核实，Claude Team 确实有 **Standard ($20-25/座/月)** 和 **Premium ($100-150/座/月)** 两个档位。1.1/1.3 的 $150 是 Premium，2.1 的 $25 是 Standard。文档未标注 tier 名称，导致读者误以为同一产品定价矛盾。
- **建议改写**: 在表格中同时列出两个档位：
  | Teams Standard | ~$25/人/月 | 小型团队（基础功能） |
  | Teams Premium | ~$150/人/月 | 需要 Claude Code 等高级功能的团队 |
  并在 1.1/1.3 同步修正，标注 "Premium"。
- **依据**: https://blog.imseankim.com/anthropic-claude-team-plan-november-pricing-update/ ; https://www.ssdnodes.com/blog/claude-code-pricing-in-2026-every-plan-explained-pro-max-api-teams/（web-searcher 核实）

### 4. `claude /config` 表述误导
- **位置**: 第 7.1 节 / 配置更新通道
- **原文摘录**: 
  ```bash
  # 通过交互式配置
  claude /config
  # 选择 Auto-update channel → latest 或 stable
  ```
- **问题**: `/config` 是 Claude Code **交互式会话内部的 slash command**（斜杠命令），不是 shell CLI 参数。读者看到 `claude /config` 会误以为是命令行用法，在 shell 中执行会报错。
- **建议改写**: 
  ```bash
  # 在 Claude Code 交互式会话中输入
  /config
  # 选择 Auto-update channel → latest 或 stable
  ```
- **依据**: https://code.claude.com/docs/en/setup（web-searcher 核实，官方文档将其列为交互式命令）

### 5. API 中转站合规风险提示缺失
- **位置**: 第 5.2 节 / 路线 A
- **原文摘录**: "通过第三方 API 中转站代理请求，支持支付宝/微信付款，按量计费。"
- **问题**: API 中转站通常未经授权分发官方 API，使用这些服务可能存在合规风险和服务条款违规。文档作为教程教授这些方案，应增加风险提示。
- **建议改写**: 在路线 A 开头添加风险提示框：
  > ⚠️ **风险提示**：第三方 API 中转站并非 Anthropic 官方授权服务，使用可能违反 Anthropic 服务条款，且存在数据隐私和安全风险。建议优先使用官方 API 或企业代理配置（路线 C）。
- **依据**: challenger [A]

## 🟢 可选改(低优先级)

### 6. Fedora/RHEL 版本要求标注
- **位置**: 第 1.1 节 / 系统要求表格
- **原文摘录**: "Fedora / RHEL | 36 及以上（社区验证）"
- **问题**: 官方文档未明确列出 Fedora/RHEL 的具体最低版本要求，但提供了 dnf 仓库。"36 及以上"的来源不够明确。
- **建议改写**: 改为 "Fedora / RHEL | 官方提供 dnf 仓库，具体最低版本请以官方文档为准" 或保留 "社区验证" 标注但补充说明 "官方未明确最低版本"。
- **依据**: https://code.claude.com/docs/en/setup（web-searcher 核实，官方文档未列具体版本）

### 7. 国内用户资源来源权威性
- **位置**: 参考来源 3
- **问题**: 大量国内用户资源来自 CSDN、掘金、博客园等中文技术社区，这些来源权威性不足，且可能存在过时或错误信息。
- **建议改写**: 在参考来源章节添加说明："国内用户资源来自社区分享，部分信息可能随官方更新而变化，建议以 Anthropic 官方文档为准。" 或优先引用官方文档覆盖的内容。
- **依据**: challenger [C]

## 💡 建议补充

### 8. 补充认证方式系统说明
- **位置**: 第 6.2 节
- **建议**: 文档提到 OAuth（浏览器认证）和 API Key（无浏览器环境）两种方式，但未系统性解释各自的适用场景和切换方法。建议补充：① OAuth 适合本地开发，API Key 适合 CI/CD；② 如何切换认证方式；③ API Key 的权限范围与 OAuth 的差异。
- **依据**: challenger [I]

### 9. 补充网络带宽要求
- **位置**: 第 1.2 节
- **建议**: 硬件要求中未提及网络带宽。对于需要频繁调用 LLM API 的工具，网络延迟和带宽对体验影响显著。建议补充最低网络要求（如 "稳定的互联网连接，建议带宽 ≥ 10 Mbps，延迟 < 200ms"）。
- **依据**: challenger [G]
