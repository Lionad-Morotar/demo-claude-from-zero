# Review: 7.2-上下文管理策略.md

## 事实准确性

### [1] "5 倍工作量/3 倍输出质量" — 需要修改
- **原文**: "5 倍工作量"、"3 倍输出质量"
- **问题**: 纯推测性修辞，无任何量化依据。
- **建议**: 删除精确数字，改为定性描述"显著提升会话效率和输出稳定性"。

### [2] "80K Token 高质量利用区" — 需要修改
- **原文**: "80K 高质量利用区"
- **问题**: Anthropic 官方文档中不存在此概念。该数字是作者基于"前 20% + 后 20%"假设的自行推导，将渐变的 U 型曲线过度简化为台阶函数。
- **建议**: 删除或改写，明确标注为"作者基于 Lost in the Middle 现象的推断"，或改为"前部和后部的信息通常更容易被模型有效利用"。

### [3] 模型版本命名 — 无需修改，建议补充
- **核实**: "Sonnet 4.6"/"Opus 4.7"/"Haiku 4.5" 命名方式属实，官方 Prompt Caching 定价文档明确使用。
- **建议**: 补充说明官方完整模型 ID 格式（如 `claude-opus-4-7`）。

### [4] "核心信息应放在前 20% 与后 20%" — 需要修改
- **问题**: 官方长上下文博客讨论了信息位置效应，但**未给出"20%"这一精确百分比**。当前官方仅建议"将长文档放在提示词顶部"。
- **建议**: 删除精确百分比，改为"将关键信息放在上下文前部或接近末尾的位置"，并引用官方"Put longform data at the top"建议。

### [5] Token 换算表 — 需要修改
- **原文**: "中文 500-700 字符/1K Token"
- **问题**: 来源不明，可能错误。现代 tokenizer 对中文通常接近 1:1 至 1:1.5。
- **建议**: 删除或大幅修正，建议通过实际 tokenizer 工具测试 Claude 的中英文切分比例。

### [6] 延迟数据 — 需要修改
- **原文**: "10K→1-2秒，100K→5-8秒，200K→10秒+"
- **问题**: 受网络、服务器负载、模型版本、地区等多重因素影响，无法作为通用规律。
- **建议**: 删除具体延迟数字，改为"延迟随上下文长度增加而显著增加，具体数值受网络、模型版本、服务器负载等因素影响"。

### [7] Lost in the Middle 准确率 — 需要修改
- **原文**: "前 75%/中 50%/后 65%"
- **问题**: 论文摘要确认存在 U 型曲线，但**未列出精确数值**。这些数字可能是从论文图表中读取的特定实验点，被泛化为通用规律。
- **建议**: 补充论文引用（arXiv:2307.03172），弱化精确百分比为"实验显示信息位于中间时准确率明显下降"，注明数据来自特定实验条件。

### [8] `/compact` 命令 + 阈值 — 部分修改
- **核实**: `/compact` 命令**属实**。
- **问题**: "80% 预警/95% 强制压缩"阈值**无官方来源**。
- **建议**: 保留 `/compact` 描述，删除阈值数字，改为"当上下文累积过多时，可主动使用 `/compact` 压缩"。

### [9] CLAUDE.md 三级体系 — 无需修改，建议补充
- **核实**: 全部属实。官方确认 Project、User、Local、Nested 四级机制。
- **建议**: 补充 Managed policy 级别（组织级），使层级描述更完整。

### [10] Tasks "会话结束后清空" — 需要修改
- **原文**: "会话结束后清空"
- **核实**: Tasks 存储在 `~/.claude/tasks/`，默认 30 天后清理，**可跨会话持久化**。
- **建议**: 修正为"Tasks 默认在本地持久化，30 天后自动清理；可通过 `CLAUDE_CODE_TASK_LIST_ID` 环境变量实现跨会话共享"。

### [11][12] Prompt Cache — 基本正确，建议补充
- **核实**: TTL（5 分钟/1 小时）和定价（1/10）均属实。
- **建议**: 补充 Prompt Cache 的最小 Token 阈值（模型不同，1024-4096 tokens）。

### [13] "健康团队 cache 命中率 50%-80%" — 需要修改
- **问题**: 不同场景下合理命中率差异巨大，阈值为作者自行设定。
- **建议**: 删除精确阈值，改为"命中率因使用场景而异，建议通过 `/usage` 或 API 响应监控实际命中率"。

### [14] 延伸阅读链接 — 需要修改
- **问题**: `docs.anthropic.com/claude/docs/claude-code` 格式与当前官方域名 `code.claude.com/docs/en/...` 不一致。
- **建议**: 替换为当前有效链接。

### [15][16] 引用链接质量 — 需要修改
- **问题**: Sanjay Krishnan 个人主页、Boris Cherny YouTube 搜索结果页引用质量差。
- **建议**: 替换为具体论文/视频链接。

## 总体评价

本章 Lost in the Middle 效应和 Prompt Cache 机制的论述方向正确，但充斥大量作者自行推导的精确数字（20%、80K、75%/50%/65%、80%/95%、50%-80%等），这些数字将渐变的实验现象过度简化为硬性阈值，严重误导读者。建议大幅弱化或删除所有无官方来源的精确数字。
