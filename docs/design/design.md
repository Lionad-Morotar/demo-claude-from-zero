## Problem Statement

为数字园区公司的产研团队做一次 90 分钟的 Claude Code 入门分享会。需要一个"从零到产物"的现场演示案例，让产品经理和研发都觉得学到了东西。

## What Makes This Cool

分享会的产物就是分享会本身的网站。你在现场用 Claude Code 从空目录开始，先研究并创作内容，再把内容变成一个漂亮的 VitePress 文档站。整个过程就是两个核心能力的活教材：AI 辅助研究写作 + 零代码建站。

## Constraints

- 总时长 90 分钟，实际搭建时间约 40-50 分钟
- 听众水平参差：devs 用了两个月 Claude Code（懂 skills/MCP），PMs 基本零基础
- 现场演示，非共创，不翻车
- 可以不需要实用价值，但必须有趣
- 用户偏好 TS+Vue 技术栈

## Premises

1. 40-50 分钟可以从空目录搭出一个内容完整、UI 漂亮的 VitePress 文档站 — **用户已确认**
2. 两个核心能力（研究写作 + 零代码建站）覆盖了两类听众的需求 — **用户已确认**
3. 应用不需要实用价值，有趣即可 — **用户已确认**
4. VitePress 是 40 分钟窗口内最可靠的技术选择 — **用户已确认**

## Approaches Considered

### Approach A: VitePress 文档站（选定）

用 VitePress 构建 "Claude Code from Zero" 文档网站。演示流程分两大阶段。

**演示时间线（90 分钟）：**

| 阶段 | 时长 | 内容 |
|------|------|------|
| 开场介绍 | 5-10 min | 自我介绍，分享会目标，设定预期 |
| 能力一：研究 + 内容创作 | 15-20 min | 用 Claude Code 研究 Claude Code 基础知识，生成网站大纲，填充各节内容 |
| 能力二：零代码建站 | 20-25 min | 用 Claude Code 把 markdown 文件变成 VitePress 站点 |
| 花活（从预设菜单中选择） | 10-15 min | 从以下候选项中选 2-3 个现场演示 |
| Q&A + 结尾 | 5-10 min | 提问、分享网站地址、下一步 |

**能力一详细流程（研究 + 内容创作）：**

1. 在空目录打开 Claude Code
2. 提示词示例："帮我研究 Claude Code 的入门知识，生成一个名为 'Claude Code from Zero' 的文档网站大纲"
3. Claude Code 生成结构化大纲（章节标题 + 每节要点）
4. 逐步填充各章节内容
5. 产出：一组结构良好的 markdown 文件

**能力二详细流程（零代码建站）：**

1. 提示词示例："把这些 markdown 文件变成一个漂亮的 VitePress 文档站"
2. Claude Code 自动执行：
   - `npx create-vitepress` 初始化项目
   - 配置 `.vitepress/config.ts`（导航、侧边栏、主题）
   - 调整样式（配色、字体、间距）
   - 运行 dev server
3. 在浏览器中展示结果
4. 现场微调（改配色、加 feature、调整布局）

**花活候选菜单（现场选 2-3 个，每个 3-5 分钟）：**

| 花活 | 提示词模板 | 预估耗时 | 受众共鸣 |
|------|-----------|----------|----------|
| 自定义 Vue 组件 | "给首页加一个交互式终端组件，模拟 Claude Code 命令行" | 3-5 min | Devs |
| 主题定制 | "把配色改成我们公司的品牌色，加一个渐变 hero 背景" | 3 min | PMs |
| 暗色模式动画 | "给暗色模式切换加一个流畅的过渡动画" | 3 min | Both |
| 全文搜索 | "给站点加上全文搜索功能" | 3 min | Both |
| 部署上线 | "把这个站点部署到 Vercel，给我一个公开 URL" | 5 min | Both |
| Mermaid 流程图 | "在文档里加一个 Mermaid 流程图展示 Claude Code 工作流" | 3 min | Devs |

排练时至少演练其中 3 个，确保每个都能在预估时间内完成。

**Effort:** S
**Risk:** Low
**Pros:**
- VitePress 专为文档设计，默认就很好看
- Markdown 直接对应内容文件，流程自然
- Vue 组件可扩展，花活空间大
- 部署简单（Vercel/Netlify 一键）
**Cons:**
- 对 devs 来说可能不够"工程感"
- 如果内容生成太慢，会挤占建站时间

### Approach B: Nuxt Content 站点（备选）

用 Nuxt + Nuxt Content 模块构建。更灵活，可以加交互功能（搜索、评论、实时预览），但脚手架时间更长，40 分钟内完成风险更高。

**Effort:** M
**Risk:** Medium
**Pros:**
- 更灵活，可加任何 Nuxt 生态功能
- 用户对 Nuxt 更熟悉
**Cons:**
- 初始化和配置时间更长
- 默认样式需要更多调整
- 40 分钟窗口内更紧张

### Approach C: 纯 HTML 单页（最简）

不用框架，直接生成一个单页 HTML 文件。最简单，但不够"酷"，对 devs 来说没有技术含量。

**Effort:** XS
**Risk:** Low
**Pros:**
- 极快，10 分钟搞定
- 零依赖，任何浏览器都能跑
**Cons:**
- 不够专业，缺乏"产物"感
- 无法展示 Claude Code 的工程能力
- 没有花活空间

## Recommended Approach

**VitePress 文档站（Approach A）**

VitePress 在"快"和"好看"之间找到了完美平衡。`npx create-vitepress` 几秒就能跑起来，默认主题已经足够漂亮，Markdown 文件就是内容，Vue 组件可以做花活。这是 40 分钟窗口内最不会翻车的选择。

## Success Criteria

- 90 分钟内完成从空目录到可访问的文档网站
- 两类听众都至少有一次"原来如此"的瞬间
- 网站内容覆盖 Claude Code 入门所需的基础知识
- 网站视觉质量达到"可以分享给外部"的水平

## Distribution Plan

- VitePress 站点部署到 Vercel 或 Netlify
- Git 仓库分享给参会者（他们可以 fork 后自定义）
- 网站地址在分享会结尾公布

## What I noticed about how you think

- 你一开始说"帮我探索通用场景"，但当你自己提出"做分享会本身的网站"时，方向瞬间清晰了。这说明你对"产研都能共鸣"这件事有很强的直觉，你只是需要一个触发点来确认自己的判断。
- 你明确拒绝了我的"过程比产物重要"前提，但最后选的方案恰好是过程和产物高度统一的。这不是矛盾，而是你对"有趣"的定义比我更宽：有趣 = 看到东西从无到有 + 拿到一个能用的结果。
- 你对"共创"的态度很务实："成功的概率非常低"。这种判断力在实际分享会策划中很重要，宁可演示也不要让观众动手翻车。
